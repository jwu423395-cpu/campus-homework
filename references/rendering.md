# Rendering API and precise figures

`render_document(task: dict, output_dir: pathlib.Path, profile: dict | None = None) -> dict`
and `style_catalog() -> dict` are exported from `scripts/campus_homework/rendering.py`.
The renderer neither solves questions nor interacts with a learning platform. Every
question must already have `review.status: "verified"` and a nonempty `solution.final`.
That status is a prerequisite, not proof of mathematical correctness. The CLI applies
the additional source/reviewer/check requirements documented in the task schema.

## Inputs and styles

- Default page: A4, 1654 × 2339 pixels at 200 dpi (rounding to whole pixels).
- `paper`: `ruled`, `blank`, `grid`, or `cream`.
- `font`: a manifest id (`wenkai`, `yozai`, `chenyu`) or an existing absolute font path.
  Font ids resolve through `assets/fonts/manifest.json`; files are relative to
  `assets/fonts`. Missing characters fall back to Wenkai and are recorded individually
  in `fonts.fallbacks`. Characters absent in both fonts cause an explicit error.
- `font_size` is pixels (default 36, supported 20–100); `line_spacing` defaults to 1.45;
  `letter_spacing` defaults to 0 pixels; `margin` defaults to 90 pixels.
- `ink`: a Pillow-compatible color; TeX requires six-digit hexadecimal `#RRGGBB`.
- `mode`: `accurate` (default) or `photo`.

`handwriting` is `off` (default) or `natural`. In natural mode, prose has small,
deterministic per-character variation. Digits, Latin mathematical variables and
supported operators in formulas use outlines from the selected handwriting font;
MathJax still determines the layout, superscripts, subscripts, fractions and
matrix bounds. Extensible notation retains its structural outlines. This is
simulated handwriting, with no claim that a person wrote or photographed it.

`ink_effect` is `flat` (default) or `ballpoint`. Natural handwriting with ballpoint
ink applies smooth pressure variation and subtle paper grain to the nontransparent
answer strokes, blending their color with the paper at the actual writing position.
It preserves stroke support, mathematical glyphs and all block coordinates. For
black ballpoint use `ink: "#202126"`; formulas are not regenerated by an image model.

Some versions of the licensed Chenyu font have a malformed TrueType hint program
that FreeType rejects as `too many function definitions`. For that exact failure,
the renderer removes hint instructions from an in-memory copy, preserving outlines
and the original font file. It records this workaround in `fonts.render_adjustments`
with the reason and `original_file_unchanged: true`. Other font errors are not hidden.

## Solution and TeX

```json
{
  "schema_version": 1,
  "assignment": {"id": "practice", "title": "自主练习", "course": "物理", "kind": "homework"},
  "questions": [{
    "id": "q1", "number": 1, "type": "calculation", "stem": "题干原文",
    "solution": {
      "steps": [{"text": "先说明已知条件。"}, {"tex": "a_n=\\frac{v^2}{R}"}],
      "final": {"tex": "a=\\sqrt{a_\\tau^2+a_n^2}"},
      "figures": []
    },
    "review": {"status": "verified"}
  }]
}
```

An item can contain `text`, `tex`, or both; when both exist, the text precedes the
formula. Final answers with `option_ids`, `values`, or `value` also have a plain-text
representation, but the main purpose is reviewed calculations and short answers.

MathJax 3.2.2 renders TeX to self-contained SVG; resvg-js 2.6.2 rasterizes it. The
supported packages are `base`, `ams`, `newcommand`, and `boldsymbol`. Common examples
include `\\vec`, `\\frac`, `\\sqrt`, `\\int`, `\\sum`, `aligned`, `cases`, `pmatrix`,
and `bmatrix`. External resources, HTML and dynamic package loading are rejected.
Invalid TeX fails the entire render, rather than producing an upload with an error
message in place of a formula. A Node batch has a 25-second timeout. Formulas that
cannot fit at an equivalent 20-pixel font size must be split into explicit steps;
they are never silently cropped. This is a documented TeX subset, not a full LaTeX
document processor.

Install the exact JavaScript dependencies with `npm ci`. Node is found on `PATH`,
or via the `CAMPUS_HOMEWORK_NODE` environment variable. The lock file also pins the
transitive XML parser to 0.9.12, replacing the deprecated 0.9.10 dependency resolution.
Runtime rendering is offline after installation.

Official API references:

- <https://docs.mathjax.org/en/v3.2/server/direct.html>
- <https://github.com/mathjax/MathJax-demos-node>
- <https://github.com/thx/resvg-js#usage>

## Parameterized figures

All coordinates below are mathematical Cartesian coordinates: x to the right,
y upwards. One uniform data-to-pixel scale is used on both axes, so circles remain
circles and geometric angles are preserved. Labels are kept inside the drawing
frame. Figures occupy the left column, with solution steps in the right column,
when the writing area is at least 650 pixels wide. Narrow workbook regions use a
stacked figure followed by steps to preserve legibility.

Force vectors start exactly at `origin`; their supplied components determine
direction and relative length. They are not inferred from prose.

```json
{"type":"force","origin":[0,0],"body":"block","axes":true,
 "forces":[{"label":"N","vector":[0,3]},
           {"label":"mg","vector":[0,-3]},
           {"label":"F","vector":[2,0]}]}
```

`body` may be `point` (default) or `block`. Geometry uses named or literal points;
arc angles are degrees measured counterclockwise from the positive x axis.

```json
{"type":"geometry","points":{"A":[0,0],"B":[4,0],"C":[0,3],"O":[2,1.5]},
 "segments":[["A","B"],["B","C"],["C","A"]],
 "circles":[{"center":"O","radius":1}],
 "vectors":[{"start":"A","end":"B","label":"v"}],
 "arcs":[{"center":"A","radius":0.6,"start":0,"end":90,"label":"θ"}]}
```

Segments can also be objects with `start`, `end`, and optional `label`.

```json
{"type":"function","expression":"sin(x)","x_range":[-3.14159,3.14159],
 "y_range":[-1.4,1.4],"samples":500}
```

Functions use a recursive arithmetic AST interpreter, never `eval`, `exec` or
general symbolic parsing. Allowed names are `x`, `pi`, `e`; allowed operators are
`+`, `-`, `*`, `/`, `**` (exponent magnitude at most 20). Allowed one-argument
functions are `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `sqrt`, `exp`, `log`,
`log10`, `sinh`, `cosh`, `tanh`, `abs`. Unknown symbols, attributes, subscripts,
statements and arbitrary calls are rejected. Sampling is limited to 50–2000 points.
Non-real/domain-error samples create gaps. Specify `y_range` when asymptotes would
otherwise dominate the automatic bounds. The sampled plot is a visualization,
not a proof of a function's behavior between samples.

## Write on an original workbook page

```json
{"workbook":{"pages":[{
  "image":"page-7.png","page_number":7,
  "regions":[{"question_id":"q1","box":[80,500,1000,650]}],
  "protected_boxes":[[0,0,1200,450]]
}]}}
```

All boxes are `[x, y, width, height]` in original-image pixels, top-left origin.
The caller must supply regions after inspecting the page. The renderer does not
pretend to detect blank space automatically. Relative paths resolve against
`task.base_dir`, then `task._base_dir`, then the current directory. Source files
are never modified. Overlapping writing regions are rejected. Blocks that would
cross a region boundary or a protected box are moved to another region or a
continuation; they are never partially clipped. Even tiny unusable regions are
safe: the answer goes to a continuation.

The clean PNG keeps every source pixel outside writing regions and every protected
pixel unchanged after decoding to RGB. This claim applies to clean PNGs, not to
lossy PDF encodings or a perspective-transformed simulated photo. Workbook pages
receive no footer/title outside their designated regions. Remaining steps are put
on new A4 continuation sheets titled with the original page number and question
number; their manifest `kind` is `continuation` and `original_pages` records the
source page references. A missing region similarly produces a question-labeled
continuation rather than overwriting the printed exercise.

## Photo composition

Photo mode requires an existing `photo_background` path. An optional
`photo_corners` array contains four background-pixel coordinates in the order
top-left, top-right, bottom-right, bottom-left. Corners must be strictly in-frame
and form a convex non-mirrored quadrilateral. Without explicit corners, the
complete page is fitted into a gentle in-frame trapezoid. A deterministic inverse
homography projects the verified paper onto the supplied background; a soft shadow
is added. No image-generation service is called, and the manifest explicitly
records that fact. It also records the background hash, all four corners and
`simulated_photo: true`. Background provenance/approval is the caller's job.

## Artifacts and validation

Return value:

```text
page_count: int
clean_pages: [absolute PNG paths]
upload_pages: [absolute JPG paths]
clean_pdf: absolute path
upload_pdf: absolute path
manifest / manifest_path: absolute layout_manifest.json path
```

`clean/page-NNN.png` is the canonical checked paper. `upload/page-NNN.jpg` is a
quality-96 JPEG with no chroma subsampling, containing the checked paper in accurate
mode or a simulated photo in photo mode. JPEG is lossy; exact pixel checks use the
clean PNG. Multi-page PDFs are local convenience previews, not photo attachments.
`formulas/` preserves each exact TeX source's SVG and PNG, keyed by SHA256.

The layout manifest records every block's box, source/step, TeX digest, parameterized
figure and uniform scale, original image hash, region, font file/hash, glyph
fallback, photo composition and output hash. It is a review aid rather than a
claim that equations have been solved correctly. When rerendering, use the paths
returned by this invocation/manifest, not a directory glob that may include older
artifacts from an earlier invocation with more pages.

Run `python -m unittest discover -s tests -p test_rendering.py -v`. Tests cover
complex TeX, invalid formulas, figure composition, font fallback, preservation of
original workbook pixels, overflow continuations, automatic pagination, complete
formula counts, safe function parsing, required photo backgrounds and in-frame
non-mirrored paper corners. Inspect representative generated PNGs at full size
before marking a rendered assignment ready for upload.
